# Sistema de repeticiones — plan de implementación

> **Para agentes:** usar superpowers:executing-plans (o subagent-driven-development). Los pasos usan casillas `- [ ]`.

**Objetivo:** grabar cada partida en el cliente y reproducirla con un visor (mapa multicapa + timeline + render del juego), con repetición de muerte, compilación antes del podio y export a vídeo/GIF.

**Arquitectura:** un grabador en el cliente se engancha a los eventos de socket que `game.ts` ya consume y los guarda (comprimidos) en IndexedDB. `game.ts` pasa a leer de una `NetSource` intercambiable (socket real o `ReplaySource`). El visor React contiene el render del juego como una de sus vistas. Una única adición al servidor: el evento de muerte con causa y autor.

**Stack:** TypeScript, React (cliente), socket.io, three/Phoenyx, IndexedDB, `CompressionStream`, `MediaRecorder`.

**Spec:** `docs/superpowers/specs/2026-11-21-replays-design.md`

## Restricciones globales

- **Sin tests unitarios** (regla del usuario). La verificación de cada tarea es `npm run typecheck` + `npm run lint` + lo indicado en el paso. La pre-commit (lefthook) ya ejecuta lint y typecheck.
- **Un commit por tarea terminada**, mensaje en español, terminado en `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Comentarios en español.
- **No hacer push** sin confirmar con el usuario.
- **No aceptar los Términos ni el CONTINUE inicial del juego** en el navegador del agente: la verificación en vivo del visor la hace el usuario (`http://localhost:5180`).
- Formato `.replay` con campo `v` (versión de formato) y `build` (versión del juego) desde el primer día.
- El modo repetición **nunca** emite al servidor ni procesa entrada de juego.
- Grabar no puede notarse: sin trabajo síncrono pesado en el bucle de render; compresión y escritura por bloques en segundo plano.
- Ajuste «guardar repeticiones»: `localStorage`, por dispositivo, activo por defecto.

## Estructura de archivos

Nuevo directorio `client/src/replay/`:
- `format.ts` — tipos del archivo `.replay` y constantes.
- `recorder.ts` — grabador.
- `store.ts` — IndexedDB, rotación, estrella, importar/exportar.
- `source.ts` — `NetSource`, `SocketSource`, `ReplaySource`.
- `clock.ts` — reloj del reproductor.
- `cam.ts` — controlador de cámara (libre, POV, orbital, guionizada).
- `Viewer.tsx` + `viewer.css` — visor.
- `DeathCam.tsx` — repetición de muerte.
- `highlights.ts` — puntuación y elección de clips.
- `export.ts` — vídeo y GIF.
- `profile.ts` — `ProfileCard` y valores por defecto.

Se modifican: `client/src/game/game.ts` (fuente de red), `client/src/game/End.tsx` (compilación), `client/src/game/Backrooms.tsx` (pantallas y entrada al visor), `client/src/game/Settings.tsx` (ajuste), `server/src/index.ts` y `shared/src/index.ts` (evento de muerte).

## Revisión previa (Review Focus)

1. Partida larguísima o pestaña oculta: el búfer y la cola de escritura no deben crecer sin límite (tope por partida y descarte con aviso).
2. IndexedDB lleno, bloqueado o no disponible (modo privado): grabar se desactiva en silencio, el juego sigue normal.
3. Repetición de otra versión de build o con formato desconocido: aviso claro, nunca pantalla en blanco ni excepción.
4. Jugador que se desconecta o entra a mitad: el reproductor debe tolerar ids que aparecen y desaparecen.
5. Salir del visor o saltar la repetición de muerte a mitad: liberar el render y devolver la fuente de red real sin dejar listeners duplicados.

### Tarea 2: Fuente de red, grabador y almacén (sin interfaz)

**Archivos:**
- Crear: `client/src/replay/source.ts` (solo `NetSource` y `SocketSource` por ahora), `recorder.ts`, `store.ts`
- Modificar: `client/src/game/game.ts` (donde usa `mp.sock`), `client/src/game/Settings.tsx`

**Interfaces:**
- Consume: `ReplayMeta`, `ReplayChunk`, `ReplayFrame`, `ReplayEvent`, `DeathInfo`.
- Produce en `source.ts`:
  - `export interface NetSource { on(ev: string, cb: (...a: any[]) => void): void; off(ev: string, cb: (...a: any[]) => void): void; emit(ev: string, ...a: any[]): void; volatile: { emit(ev: string, ...a: any[]): void }; readonly replay: boolean }`
  - `export function socketSource(sock: Sock): NetSource` (envuelve el socket; `replay=false`).
- Produce en `recorder.ts`:
  - `export class Recorder { constructor(src: NetSource, meta: Omit<ReplayMeta, 'id' | 'durationMs' | 'size' | 'starred'>); own(x: number, y: number, z: number, yaw: number, pitch: number): void; tail(ms: number): { frames: ReplayFrame[]; events: ReplayEvent[] }; stop(): Promise<string | null> }` (`stop` devuelve el id guardado o `null` si no se pudo).
- Produce en `store.ts`:
  - `export async function saveReplay(meta: ReplayMeta, chunks: Blob[]): Promise<void>`
  - `export async function listReplays(): Promise<ReplayMeta[]>`
  - `export async function loadReplay(id: string): Promise<{ meta: ReplayMeta; chunks: ReplayChunk[] } | null>`
  - `export async function starReplay(id: string, on: boolean): Promise<void>`
  - `export async function deleteReplay(id: string): Promise<void>`
  - `export async function exportReplay(id: string): Promise<Blob>` / `export async function importReplay(file: File): Promise<ReplayMeta>`
  - Rotación: al guardar, si hay más de 10 sin estrella, borra las más antiguas sin estrella.
  - `export const recordingOn: () => boolean` / `setRecordingOn(v: boolean)` sobre `localStorage` (clave `bk.replay`, por defecto `true`, con `try/catch`).

- [ ] **Paso 1:** crear `NetSource` y `socketSource`. En `game.ts`, sustituir los usos de `mp.sock` por una `NetSource` creada con `socketSource(mp.sock)` en un único punto (`mp.net`), sin cambiar comportamiento. Los usos de `Sock` que no entren en la interfaz (p. ej. `.volatile`) se cubren con la propia interfaz.
- [ ] **Paso 2:** `recorder.ts`: suscribirse a `players`, `world`, `dead`, `deathInfo`, `blastFx`, `adminFx`, `rlog`, `elevator` (los eventos que existan), anotar `t` relativo al inicio. Frames `players` y `world` en delta contra el anterior (campos iguales omitidos); fotograma clave completo cada 5 s. `own()` lo llama `game.ts` a 30 Hz. Mantener en memoria solo un búfer circular de los últimos 15 s (para `tail`) y volcar bloques cerrados (cada ~5 s) a una cola que comprime con `CompressionStream('gzip')` y los entrega a `store`. Tope: 20 MB comprimidos por partida; al pasarse, parar la grabación y marcar la partida como truncada.
- [ ] **Paso 3:** `store.ts` sobre IndexedDB (`replays` para metadatos, `blobs` para bloques). Todo en `try/catch`: si IndexedDB falla, `saveReplay` devuelve sin lanzar y el grabador queda inerte.
- [ ] **Paso 4:** arrancar el `Recorder` al empezar la ronda (cuando `recordingOn()`), llamar `own()` desde el bucle de `game.ts` a 30 Hz, y `stop()` al terminar la ronda o salir. Añadir en `Settings.tsx` un interruptor «Guardar repeticiones».
- [ ] **Paso 5:** `npm run typecheck && npm run lint`. Verificación: el usuario juega una ronda corta y comprueba en DevTools → Application → IndexedDB que aparece una partida con tamaño razonable (esperado: 1–3 MB para ~10 min) y que los FPS no cambian.
- [ ] **Paso 6:** commit «Repeticiones: la partida se graba en el cliente y se guarda en IndexedDB».

### Tarea 3: Reproductor y render del juego en modo repetición

**Archivos:**
- Modificar: `client/src/replay/source.ts`, `client/src/game/game.ts`
- Crear: `client/src/replay/clock.ts`, `client/src/replay/cam.ts`

**Interfaces:**
- Consume: `NetSource`, `ReplayChunk`, `ReplayMeta`, `loadReplay`.
- Produce en `clock.ts`:
  - `export class ReplayClock { t: number; speed: number; playing: boolean; readonly end: number; seek(t: number): void; tick(dtMs: number): void; onSeek(cb: () => void): () => void }`
- Produce en `source.ts`:
  - `export class ReplaySource implements NetSource` con `constructor(chunks: ReplayChunk[], clock: ReplayClock)`, `replay = true`, que reconstruye el estado en `clock.t` (parte del fotograma clave anterior y aplica deltas), interpola `players` y `world` entre fotogramas y dispara los mismos eventos de socket (`players`, `world`, `dead`, ...) al avanzar. `emit` y `volatile.emit` no hacen nada.
- Produce en `cam.ts`:
  - `export type CamMode = { k: 'free' } | { k: 'pov'; id: string } | { k: 'orbit'; id: string } | { k: 'script'; fn: (t: number) => { x: number; y: number; z: number; yaw: number; pitch: number; fov?: number } }`
  - `export class ReplayCam { mode: CamMode; setMode(m: CamMode): void; update(dt: number, src: ReplaySource): { x: number; y: number; z: number; yaw: number; pitch: number; fov?: number } }`

- [ ] **Paso 1:** `ReplayClock` y `ReplaySource` (reconstrucción desde fotograma clave, interpolación, disparo de eventos, `seek` hacia atrás reiniciando desde el clave anterior).
- [ ] **Paso 2:** en `game.ts`, un modo `replay` al crearse con una `NetSource` con `replay=true`: sin `sendState`, sin entrada de teclado/ratón/mando para jugar, sin `emit`; la cámara sale de `ReplayCam` (libre: vuelo con WASD+ratón que atraviesa paredes y capas; POV: usa la cámara propia grabada si es el grabador, si no `yaw/pitch` de `players`, y si falta, dirección de movimiento).
- [ ] **Paso 3:** al salir del modo repetición, destruir el render y los listeners (`offNet`) sin dejar nada colgado.
- [ ] **Paso 4:** `npm run typecheck && npm run lint`. Verificación: un punto de entrada temporal (`?replay=<id>` en dev) abre la partida guardada en la Tarea 2; el usuario comprueba movimiento de jugadores, entidades, cámara libre entre plantas y POV.
- [ ] **Paso 5:** commit «Repeticiones: reproductor que alimenta el juego real con cámara libre y punto de vista».
